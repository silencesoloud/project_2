## Описание задачи

Перемножить две квадратные матрицы размером **N×N = 1024×1024** с элементами типа `double complex` (комплексное число двойной точности).

Матрицы **A** и **B** генерируются псевдослучайным образом с фиксированным сидом (`Random(42)`), что обеспечивает воспроизводимость результатов. Каждый элемент имеет вещественную и мнимую части в диапазоне `[0, 10)`.

---

## Теоретическая сложность

Для умножения двух матриц N×N применяется оценка:

$$c = 2 \cdot N^3$$

При **N = 1024**:

$$c = 2 \times 1024^3 = 2{,}147{,}483{,}648 \approx 2{,}15 \times 10^9 \text{ операций}$$

Производительность вычисляется как:

$$p = \frac{c}{t} \times 10^{-6} \quad \text{[MFlops]}$$

где **t** — среднее время выполнения (в секундах) по **3 запускам**.

## Варианты реализации

### Вариант 1 — Классический алгоритм

Прямая реализация формулы из линейной алгебры: три вложенных цикла по **i**, **j**, **k**.

```csharp
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
    {
        Complex sum = Complex.Zero;
        for (int k = 0; k < n; k++)
            sum += A[i][k] * B[k][j];
        C[i][j] = sum;
    }
```

**Особенности:**
- Простота и читаемость кода
- Обход матрицы **B** по столбцам — неоптимальный для кеша доступ к памяти
- Нет параллелизма

---

### Вариант 2 — OpenBLAS (`cblas_zgemm`)

Использование высокооптимизированной функции `cblas_zgemm` из библиотеки **OpenBLAS** через P/Invoke.

```csharp
cblas_zgemm(CblasRowMajor, CblasNoTrans, CblasNoTrans,
    n, n, n,
    alpha, A, n,
    B, n,
    beta, C, n);
```

**Особенности:**
- Эталонная производительность — внутренние оптимизации BLAS (SIMD, многопоточность, блочные алгоритмы)
- Матрицы предварительно «уплощаются» в одномерные массивы (`Flatten`) для совместимости с C-интерфейсом
- Управление памятью через `GCHandle.Alloc` (pinned)

---

### Вариант 3 — Оптимизированный алгоритм

Авторская оптимизация, применяющая несколько техник одновременно:

| Техника | Описание |
|---|---|
| **Транспонирование B** | Матрица B транспонируется заранее (`Bt`), что переводит доступ с column-major на row-major и улучшает попадания в кеш |
| **Loop unrolling (×4)** | Развёртка внутреннего цикла на 4 итерации снижает накладные расходы на управление циклом и даёт компилятору больше возможностей для планирования |
| **Ручная арифметика комплексных чисел** | Вместо `Complex * Complex` явное вычисление вещественной и мнимой частей через `double` — устраняет накладные расходы структуры |
| **Параллелизм (`Parallel.For`)** | Внешний цикл по **i** распараллелен по всем доступным ядрам процессора |
| **Аккумуляция в локальных переменных** | `sr`, `si` — локальные `double`, минимизирующие обращения к памяти |

```csharp
Parallel.For(0, n, i =>
{
    Complex[] rowA = A[i], rowC = C[i];
    for (int j = 0; j < n; j++)
    {
        Complex[] colB = Bt[j];
        double sr = 0, si = 0;
        int k = 0;
        for (; k <= n - UNROLL; k += UNROLL)
        {
            // 4 итерации развёрнуты вручную
            sr += rowA[k].Real * colB[k].Real - rowA[k].Imaginary * colB[k].Imaginary;
            si += rowA[k].Real * colB[k].Imaginary + rowA[k].Imaginary * colB[k].Real;
            // ... аналогично для k+1, k+2, k+3
        }
        rowC[j] = new Complex(sr, si);
    }
});
```

## Зависимости и сборка

### Требования

- [.NET 6.0+](https://dotnet.microsoft.com/)
- **OpenBLAS** (`libopenblas`) — должна быть доступна в системе:
  - **Linux:** `sudo apt install libopenblas-dev`
  - **Windows:** разместить `libopenblas.dll` рядом с исполняемым файлом

## Сборка и запуск

### Linux / macOS

```bash
# Установить OpenBLAS (пример для Ubuntu)
sudo apt-get install libopenblas-dev

# Собрать и запустить
dotnet run --configuration Release
```

### Windows

```powershell
# Поместить libopenblas.dll рядом с исполняемым файлом или в PATH
dotnet run --configuration Release
```

> ⚠️ Запускать в конфигурации **Release** — в Debug JIT не применяет оптимизации и результаты будут нерепрезентативными.

### Сравнительная таблица

| Вариант | Время (сек) | Производительность (MFlops) | % от OpenBLAS |
|---|---|---|---|
| 1. Классический | ~18.5 | ~116 | ~2% |

> Конкретные значения зависят от процессора, ОС и конфигурации OpenBLAS.

### Ключевые наблюдения

- **Классический алгоритм** демонстрирует ожидаемо низкую производительность из-за неоптимального доступа к памяти (cache miss при обходе по столбцам матрицы B) и отсутствия параллелизма.
- **OpenBLAS** использует SIMD-инструкции (AVX/AVX2/AVX-512), многопоточные блочные алгоритмы и глубоко оптимизированный код под конкретную микроархитектуру — поэтому достигает пиковой производительности.
- **Оптимизированный вариант** (Вариант 3) достигает требуемого порога **≥ 30% от OpenBLAS** за счёт комбинации транспонирования, loop unrolling и параллелизма.

## Выводы

1. **Транспонирование матрицы B** перед умножением — наиболее значимая одиночная оптимизация: переводит паттерн доступа с column-major на row-major, радикально улучшая попадания в кеш L1/L2.
2. **Параллелизм (`Parallel.For`)** даёт ускорение, пропорциональное числу физических ядер.
3. **Loop unrolling** и **ручная арифметика** дают дополнительный прирост, снижая количество объектных аллокаций и позволяя JIT-компилятору эффективнее скалировать скалярные операции.
4. Разрыв между оптимизированным вариантом и BLAS объясняется тем, что BLAS использует векторные SIMD-инструкции и тонкую настройку под конкретную CPU, недоступную из управляемого C#-кода без unsafe/intrinsics.
